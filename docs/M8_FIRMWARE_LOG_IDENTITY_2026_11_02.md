Do not retroactively stamp old logs from file name or repository.

## Protocol (new firmware only)

Every completed, fully disarmed `#M8S00_BEGIN,1` ... `#M8S00_END` frame begins with a NEW **MCU-generated** line:

```text
#M8S00_BEGIN,1
M8S00_FW,proto=1,sha=<40 lowercase Git hex>,dirty=0,branch=<sanitized>,builtUtc=<UTC>,target=STM32F767ZI
M8S00_META,STOP,...
...
M8S153,enable=0,last=0,...
#M8S00_END
```

The **actual** 40-hex SHA is generated by `tools/stamp_firmware_build.ps1` calling `git rev-parse --verify HEAD` locally **before compiling**; it is NOT hardcoded into the source commit (which would be a self-referential Git SHA). `dirty=1` means tracked/untracked file changes existed at stamping; exact commit-only attribution then is refused by PowerShell. `builtUtc` is host UTC when header was generated, not MCU RTC nor physical flash time. `branch` is sanitized, not a security proof. The generated `Core/Inc/firmware_build_id_generated.h` is ignored by Git. Both CubeIDE Debug and Release `.cproject` configurations have the same PowerShell pre-build step. If stamping/creation fails, `main.c` has **no fallback header**: fail the build rather than silently emit an old/wrong SHA.

The identity tells you which Git **source HEAD was used by the compiler**, subject to dirty status. It does not authenticate the ELF bytes nor prove which binary was physically programmed until the STM32 itself emits the line after flashing. For an incremental build up-to-date/no compile, the ELF naturally retains its previous identity: use **Clean Build** to intentionally build the newest HEAD. Distinguish host tests, actual CubeIDE build, programmed ELF and physical-control validation.

## Workflow (native PowerShell for collection)

1. Preserve any local edits, update to the intended commit, inspect `git status --short` (must be empty other than ignored generated header/logs). CubeIDE **Project → Clean** and **Build**. Verify build console prints `STAMPED firmware Git commit=...`; verify `Core/Inc/firmware_build_id_generated.h` matches `git rev-parse HEAD`. Failed stamping is NOT a valid build.
2. Debug/program ONLY the chosen, compiled `.elf` when it is safe, Resume MCU. Do not assume Git HEAD changed the flashed MCU.
3. On a supported chassis with verified NC/STOP/independent motor-power cutoff, run one PowerShell COM capture command (COM4 example): 

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\capture_m8_s152.ps1 -Port COM4 -Baud 115200 -ExpectedRuns 1 -TimeoutSeconds 180 -OutputDirectory .\logs
```

The script obtains **expected SHA** from local Git HEAD automatically, checks **actual SHA in each MCU frame** and checks dirty=0. You can override explicitly with `-ExpectedCommit <full-40-hex-SHA>` when intentionally testing a different checked-out/previous commit. If the file has missing/malformed firmware identity, if SHA mismatches or dirty=1, the script **keeps the TXT and exits with an error**, never claims verified firmware data.
4. Stop/disarm and verify **physical standstill** before short USER; no terminal app, Python, S11 streaming or Live Expressions for data transfer. The same S15.2 test order/protocol remains. These instructions do **NOT** enable S15.3; `M8S153 last=0` means firmware has not latched the new controller. S15.3 active motor testing remains gated on physical current/coast/NC clearance; firmware identity alone is not safety clearance.

## Reproducibility across chat sessions

Keep the **original TXT files** unchanged, including full `M8S00_FW` and all end markers. Include the Git commit link and test purpose with a saved file when available. Future sessions group by exact `sha` plus `dirty`, by `M8S153 last`, `M8S152_META kind/dirL`, and by load/starting positions, **not** by filename timestamp alone. Older captures without `M8S00_FW` remain historical evidence with **unknown exact firmware**, even if code format suggests a rough milestone.
